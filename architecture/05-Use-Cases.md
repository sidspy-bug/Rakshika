# Use Cases

Rakshika is driven by a small set of critical user journeys that must work reliably under stress.

## Core Use Cases

### 1. Onboarding and Account Setup

The user installs the app, creates an account, configures profile details, and adds emergency contacts and safety preferences.

### 2. Trigger an Emergency

The user activates SOS through a primary button or alternate trigger such as shake, voice, or shortcut. The system creates an emergency record and begins fan-out.

### 3. Notify Contacts and Responders

The platform alerts emergency contacts, sends push notifications, and broadcasts the event to nearby eligible community responders.

### 4. Share Live Location

The app continuously updates location during the emergency and shares it with authorized viewers.

### 5. Capture Evidence

The app records or uploads audio, video, and metadata so evidence is preserved securely for later review.

### 6. Use AI Assistance

The user receives guided support, safe route suggestions, and incident summaries when available.

### 7. Responder Accepts Emergency

A nearby volunteer views the alert, accepts the emergency, and navigates toward the incident.

### 8. Monitor Emergency Progress

The system tracks whether the emergency is active, acknowledged, in progress, or resolved.

### 9. Admin Reviews Activity

An administrator audits incidents, views analytics, and monitors abuse or operational issues.

### 10. Resolve and Review

After the emergency, the user can review the timeline, evidence, and response history.

## Design Implication

These use cases should map directly to screens, API endpoints, service responsibilities, and database records.
